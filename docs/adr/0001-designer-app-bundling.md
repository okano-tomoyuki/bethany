# 0001. デザイナーアプリケーションを別途セットで配布する

- 状態: 承認
- 日付: 2026-09-26

## 背景

本ライブラリは RAD Studio が持つようなビジュアルフォームデザイナーを含まない方針で進めてきた
([todo.md](../../todo.md) の配布方針・市場調査を参照)。

市場調査の結果、LCL を DLL 化して C/C++ 等に公開する取り組み(liblcl)は既に存在するが、
C++Builder のようなオブジェクト指向ラッパー(プロパティ構文、クラス階層)を提供する例は見当たらなかった。
一方で、当時 C++Builder を使っていた世代がこのライブラリに期待するのは、単なる API の有無だけでなく、
デザイナーによる生産性(ウィジェットを配置してプロパティを設定するだけで画面ができる体験)でもあると考えられる。

これと同種の課題には、[cpp_tk](https://github.com/okano-tomoyuki/cpp_tk)(C++ 向け Tcl/Tk ラッパー)
と [tk-designer](https://github.com/okano-tomoyuki/tk-designer)(そのビジュアルデザイナー、VS Code 拡張)の
組み合わせで既に取り組んでおり、DSL + コード生成 + VS Code 拡張という形式が機能する実績がある。

## 検討した選択肢

- **デザイナー無しでライブラリのみ提供**: コードのみで完結し実装コストは最小だが、
  当時 C++Builder に慣れた層にとって生産性の面で見劣りする。
- **IDE 統合(独自 IDE 化)**: 開発コストが非常に大きく、tk-designer で得た知見(VS Code 拡張という枠組み)を活かしにくい。
- **tk-designer 同様の VS Code 拡張 + DSL + コード生成**: 実績のある形式を踏襲でき、
  開発コストを抑えつつ tk-designer の知見(marker ベースのコード生成、DSL 設計等)を転用できる。

## 決定

**tk-designer と同様に、VS Code 拡張 + DSL + コード生成という形でデザイナーアプリケーションを別途開発し、
本ライブラリとセットで配布する。**

デザイナー本体は別リポジトリ(仮称、未作成)として管理し、本リポジトリは C++ ラッパーライブラリの実装に専念する。

## 影響

- DSL からのコード生成が無理なく成立するよう、C++ 側のオブジェクトモデル、特に初期化方式を見直す必要がある
  ([ADR 0003](0003-two-phase-initialization.md))。
- オブジェクトモデルは C++Builder に極力揃える方針を維持する([ADR 0002](0002-object-model-fidelity.md))。
  DSL の語彙(ウィジェット名・プロパティ名・イベント名)もこれに合わせて設計することになる。
- デザイナー本体の設計・実装は本リポジトリのスコープ外であり、着手時期は未定。
