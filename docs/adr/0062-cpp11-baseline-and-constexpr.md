# 0062. C++11 を下限とし、ヘッダの定数を constexpr にする

- 状態: 承認
- 日付: 2026-09-30

## 背景

ヘッダの定数(色 `clRed`・カーソル `crHourGlass`・`mrOk`・ショートカットの修飾 等。99 個)は、名前空間で
`const TColor clRed = 0x0000FF;` のように宣言していた。

- C++ では、名前空間の `const` の変数は内部リンケージになる(`static` を付けたのと同じ)。ヘッダに書いてもインクルードした翻訳単位ごとの
  定数になるだけで、多重定義にも ODR の違反にもならない。整数・列挙型を定数式で初期化したものは、定数式としても使える。
- そのため今の書き方は正しいが、現代の C++ では `constexpr`(C++17 以降は `inline constexpr`)で書くのが一般的で、
  「コンパイル時の定数である」という意図も明確になる。`static constexpr` はクラスのメンバの定数の書き方で、名前空間では `static` は余分。

あわせて、C++ の版の下限を決める必要があった。C++17 以降にすれば `inline constexpr`(プログラム全体で 1 つの定数)が使え、
`Set` の定数(`mbYesNo` 等)もヘッダに書ける。一方で、古いコンパイラでも使えることを優先したい。

## 検討した選択肢

- 選択肢A: C++11 のまま、`const` を `constexpr` にする。
- 選択肢B: C++17 以降を要件にし、`inline constexpr` にする。
- 選択肢C: `const` のままにする。

## 決定

**選択肢A を選ぶ。**

- **C++ の版の下限は C++11 とする**(ラムダが使える版。イベントのハンドラをラムダで割り当てるため、これより前には下げられない)。
  1.0 以降も、古いコンパイラで使えることを優先して、この下限を保つ。ヘッダと `src/` は C++11 の範囲で書く。
- 名前空間の定数(`TColor`・`TCursor`・`TModalResult`・`TShortCut`)を `constexpr` にする。`static` は付けない。
- `Set` の定数(`mbYesNo`・`mbYesNoCancel`・`mbOKCancel` 等)は、C++11 では `Set` をコンパイル時に作れない(`constexpr` の関数が
  1 つの return 文に限られ、`operator<<` が値を書き換える)ため、これまでどおり `extern const` で宣言し、`beth.cpp` で定義する。
- Python の生成器(`gen_api.py`)は、`constexpr` の定数も読むようにする(生成されるコードは変わらない)。

## 影響

- 利用者のコードは変わらない(値も型も同じ)。定数を定数式でない値で初期化する誤りは、その場でコンパイルエラーになる。
- C++17 の機能(`inline` 変数・`if constexpr`・構造化束縛等)は、ヘッダと `src/` では使わない。
