# 0002. オブジェクトモデルは C++Builder に極力揃える

- 状態: 承認(既存方針の再確認)
- 日付: 2026-09-26

## 背景

Phase 1〜5 の実装を通じ、`Property<T>` による軽量プロパティプロキシ、`TObject` 基底クラス、
`Canvas`/`Pen`/`Brush`/`Font` の合成構造など、C++Builder の VCL に近いオブジェクトモデルを既に採用してきた
([todo.md](../../todo.md) の Phase 4・Phase 5 を参照)。

デザイナーアプリケーションとセットでの配布([ADR 0001](0001-designer-app-bundling.md))を決めたことで、
DSL からのコード生成を見据えたときにこの方針を継続すべきか、改めて論点になった
(liblcl のようなフラット API に寄せる方が生成コードは単純になる可能性があるため)。

## 検討した選択肢

- **フラットな C API スタイルを直接 C++ から使わせる(liblcl 方式)**: 実装・コード生成ともに単純だが、
  「C++Builder と同等の書き味」という本来の目的([docs/vision.md](../vision.md))を満たさない。
- **C++Builder に極力寄せたオブジェクトモデルを継続**: これまでの実装(`Property<T>`、`TObject` 階層、
  `Canvas` の合成構造)と整合し、生成コードも C++Builder 経験者に馴染みやすい。

## 決定

**既存方針を継続する。** オブジェクトモデルの忠実さを優先し、デザイナーの DSL・コード生成もこのモデルに合わせて設計する。

## 影響

- DSL のウィジェット定義・プロパティ・イベントの語彙は、現状の `beth.hpp` の構造
  (クラス名は VCL 由来の `TXxx`、プロパティは `Property<T>`、イベントは `std::function` ベース)を踏襲する。
- 現状の初期化方式(コンストラクタで `TObject& parent` を受け取り即座に生成)は、
  コード生成の観点では不向きな面がある。これは本 ADR の対象ではなく [ADR 0003](0003-two-phase-initialization.md) で扱う。
