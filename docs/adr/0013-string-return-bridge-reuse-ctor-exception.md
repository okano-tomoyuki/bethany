# 0013. 文字列はスレッドローカルバッファ経由で返し、イベントのブリッジは再利用し、コンストラクタが例外を投げたら LCL オブジェクトを破棄する

- 状態: 承認
- 日付: 2026-09-26

## 背景

todo.md に残っていた既知の問題のうち、次の 3 点に対応した。

1. **文字列を返す関数のダングリングポインタ。** `PChar(TControl(Obj).Caption)` のように、一時的な `AnsiString` を
   `PChar` にキャストしてそのまま返していた。関数を抜けると参照カウントが 0 になって解放されるため、
   厳密には呼び出し側は解放済みのメモリを指すポインタを受け取っていた(コンパイラの実装や最適化に運を任せていた状態)。
2. **イベント登録のブリッジの蓄積。** `beth_TControl_SetOnClick` 等の登録関数は、呼ぶたびに新しい `TCallbackBridge` を
   `Owner.Create` していた。C API を直接使う場合(C++ ラッパー経由では初回しか呼ばれないため問題にならない)、
   同じイベントに繰り返し登録すると古いブリッジが Owner に残り続ける。破棄されずリークするわけではないが無駄が積み重なる。
3. **コンストラクタが例外を投げたときの取り残し。** `TComponent` の派生クラスのコンストラクタが例外を投げると、
   基底クラス部分(`TComponent` 自身)は構築済みのため、その部分のデストラクタは呼ばれる。
   しかしラッパーの生存期間は「LCL オブジェクトの破棄通知で delete される」ことを前提にしており([ADR 0008](0008-wrapper-lifetime-follows-lcl.md))、
   自分から LCL オブジェクトを破棄する経路が無かった。結果、生成済みの LCL オブジェクトだけが取り残される。

## 決定

1. **文字列を返す関数は、スレッドごとのバッファ(`threadvar`)に値を保持してから `PChar` を返す`関数 `ReturnStr` を経由する。**
   これにより、戻り値は「同じスレッドで次に文字列を返す関数を呼ぶまで有効」になる。C API のヘッダにこの約束を明記した。
   2 つの戻り値を同時に使う場合(1 つの `printf` 呼び出しに 2 つ並べる等)は、呼び出し側でどちらかをコピーする必要がある。
2. **ブリッジは Owner ごとに 1 つだけ使い回す。** イベントに現在設定されているメソッドの `Data`(メソッドの持ち主のインスタンス)を見て、
   それが Owner の持つこのライブラリのブリッジなら、新しく作らずコールバックと利用者データだけ差し替える。
   別の Owner のブリッジ(あり得ないが、Obj の Owner が変わった場合の保険)や、ブリッジでない値(未設定など)なら新しく作る。
   コールバックに `nil`/`NULL` を渡すとハンドラを解除できる(ブリッジ自体は残すが、`Assigned(FCallback)` が False になるので呼ばれない。
   実行中のブリッジ自身を破棄しないため)。
3. **`TComponent` の派生クラスのコンストラクタが例外を投げたら、`TComponent` のデストラクタで LCL オブジェクトを破棄する。**
   通常の破棄(`Free()` や Owner の連鎖破棄)では LCL オブジェクトの破棄通知で delete されるため、
   このデストラクタが呼ばれる時点で LCL オブジェクトは既に破棄の途中にある。これと、コンストラクタの例外による巻き戻しを、
   「破棄通知経由で delete されたか」を示すフラグ `freedByLcl_`(`FreeNotifyTrampoline` の中だけで立てる)で区別する。
   立っていなければ、レジストリから自身を外した後で `beth_TComponent_Destroy` を呼ぶ(先に外すため、この破棄に伴う
   破棄通知や `OnDestroy` はもう存在しないラッパーには届かない)。

## 影響

- C API の文字列は、値を保持したい場合や 2 つ以上の戻り値を同時に使う場合、呼び出し側でコピーが必要になる
  (今回のテストでは 1 つの `printf` に 1 つだけ渡す形にしている)。
- C API を直接使う場合、同じイベントに繰り返し登録してもブリッジが蓄積しなくなり、`NULL` を渡すことでハンドラを解除できるようになった。
- コンストラクタが例外を投げても LCL オブジェクトが残らなくなった。ただし、例外を投げる派生クラスの単体テストはまだ書いていない。
