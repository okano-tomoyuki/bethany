# 0065. デザイナーのビューを、プロジェクトの作成から始めて生成先のコードも出すものにする

- 状態: 承認
- 日付: 2026-10-03

## 背景

アクティビティバーの Bethany Designer のビュー(フォームのビュー)の、2 つの点を改める。

### 空のワークスペースでの案内

- フォームが 1 つも無いとき、ビューは「新しいフォームを作成」の案内を出していた(`viewsWelcome`)。
- しかしコード生成の設定(言語・出力先・コメントの言語)は、プロジェクトファイル(`*.bfproj.json`)に持つ([project-spec.md](../designer/project-spec.md) §5)。
  - どのプロジェクトにも属さないフォームはコードを生成できない。
  - そのため、フォームから始めると、後でプロジェクトへの追加を求められる。
- C++Builder でも、新しいアプリケーションはプロジェクトとして作り、フォームはプロジェクトに加わる。

### 生成先のコードを開く手間

- ビューにはフォームとプロジェクトしか出なかった。
- 生成したコード(`MainForm.cpp`・`MainForm.hpp`・`MainForm.py`、起動部分の `Project1.cpp` 等)を開くには、エクスプローラーに切り替えてファイルを探す必要があった。
- C++Builder のプロジェクトマネージャーは、フォームのユニットの下に `.cpp`・`.h`・`.dfm` を並べ、そこから開ける。

## 検討した選択肢

### 空のワークスペースでの案内

- 選択肢A: 「新しいフォームを作成」のまま(利点: 変更が無い / 欠点: フォームを作った後にプロジェクトを作ることになり、順序が逆になる)
- 選択肢B: 「新しいプロジェクトを作成」と「新しいフォームを作成」の両方を出す(利点: どちらからも始められる / 欠点: プロジェクトに属さないフォームを作る道を勧めることになる)
- 選択肢C: 「新しいプロジェクトを作成」だけを出す(利点: フォームをプロジェクトで管理する前提に合う / 欠点: フォームだけを作るには見出しの「+」を使う)

### 生成先のコード

- 選択肢A: フォームの右クリックに「生成したコードを開く」を加える(利点: ビューが長くならない / 欠点: ファイルが見えず、開くのに操作が増える)
- 選択肢B: フォームの下に生成先のファイルを子として出す(利点: C++Builder のプロジェクトマネージャーと同じく、見えてすぐ開ける / 欠点: 項目が増える)

## 決定

### 空のワークスペースでの案内

選択肢C にする。

- プロジェクトもフォームも無いときは、「新しいプロジェクトを作成」のボタン(`bethanyDesigner.newProject`)を出す。
- 説明文では、フォームはプロジェクトに加えて管理し、プロジェクトの「+」で作ると案内する。
- 新しいプロジェクトの名前と作成先のフォルダは、新しいフォームと同じ入力欄で入力してもらう(それまでは、ワークスペースの先頭のフォルダに
  `Project1` 等の名前で黙って作っていた)。
  - 名前の初期値は `Project1`・`Project2`…の空いているもの(C++Builder と同じ)。フォルダは入力欄のボタンで変えられる。
  - 名前はプロジェクトファイルと起動部分のファイル名(`<名前>.bfproj.json`・`<名前>.cpp`・`<名前>.py`)になる。
    そのため、Windows のファイル名に使えない文字(`\ / : * ? " < > |`、制御文字)・末尾のピリオドと空白・予約名(`CON`・`NUL`・`COM1` 等)は使えない(`projectNameProblem`)。
  - 同じフォルダに同じ名前のフォームがあれば使えない(起動部分のコードがフォームのコードと同じファイル名になる)。
  - ワークスペースの外のフォルダは選べない(フォームのビューに出ないため)。
  - フォームの「メインフォームに設定」「プロジェクトに追加」で、プロジェクトが無いときに作るプロジェクトも、同じく名前を入力してもらう。
- フォームだけを作る道(見出しの「+」、エクスプローラーの右クリック、「新しいファイル」)は残す。

### 生成先のコード

選択肢B にする。

- プロジェクトに属するフォームを折りたたんだ状態で出す。展開すると、生成先の C++ のヘッダ・ソースと Python のモジュールが子として並ぶ。
  - 出力先は、コード生成と同じく、フォームを含むすべてのプロジェクトの `codegen` から求める(`formCodegenSettings`・`resolveTargets`)。
    `headerDir`・`sourceDir`・`moduleDir`・`overrides` も反映する。
  - 生成する言語が無いプロジェクトのフォームと、どのプロジェクトにも属さないフォームは展開できない(コードを生成しないため)。
- プロジェクトの下には、フォームより前に起動部分のコード(`cpp.main`・`python.main`)を出す。
- クリックするとテキストエディタで開く。
  - アイコンは、ファイルアイコンのテーマの拡張子ごとのものにする(`resourceUri` と `ThemeIcon.File`)。
  - まだ生成していないファイルには「未生成」と表示し、クリックしても開かない。
- 生成先の子は、展開したときに求める。フォームのファイルを読んでフォームの名前を確かめるので、検証を通らないフォームでは子を出さない。

## 影響

- 空のフォルダから始めると、プロジェクトを作ってからフォームを加える順になる。プロジェクトの設定の既定値は変わらない(C++ と Python の両方)。
- デザイナーのコード生成で新しくファイルを作ると、ビューを更新して「未生成」の表示を消す。
  - デザイナーを通さずに生成先のファイルを作る・消すと、表示はすぐには変わらない。
  - 生成先のファイルをすべて見張るのは、ワークスペースの多くのファイルを見張ることになるため、今は見張らない。
  - その場合は、フォームを展開し直すか、ビューの更新のボタンで反映する。
- ビューの項目が増える。フォームを折りたたんだ状態で出すことで、長くなるのを抑える。
