# 0066. デザイナーでフォーム・プロジェクトファイルを保存したときにコードを生成する

- 状態: 承認
- 日付: 2026-10-03

## 背景

デザイナーでは、フォーム(`*.bfm.json`)・プロジェクトファイル(`*.bfproj.json`)の保存と、コードの生成が別々の操作だった。

- 生成は、利用者の明示的な操作(「コードを生成」)で行っていた。この方針は tk-designer ADR 0010 から引き継いだもの([ADR 0035](0035-designer-in-this-repository.md))。
- そのため、フォームを直して保存しても、生成し忘れると C++・Python のコードが古いままになる。
- C++Builder では、フォームを保存するとユニット(`.h`・`.cpp`)も更新される。利用者は、保存すればコードも最新になると期待する。

一方、保存のたびに生成すると、明示的な操作のときと同じ振る舞いでは邪魔になる点がある。

- 生成する区間が手で編集されていると、上書きしてよいかをモーダルのダイアログで聞いていた。
- どのプロジェクトにも属さないフォームでは、プロジェクトへの追加を案内していた。
- 自動保存(`files.autoSave`)では、数秒ごとに保存される。

## 検討した選択肢

### 有効・無効の設定

- 選択肢A: 常に保存したときに生成する(利点: 設定が要らない / 欠点: 生成先を手で管理したい利用者が止められない)
- 選択肢B: VS Code の設定にする(利点: 利用者ごとに選べる / 欠点: チームの中で振る舞いがそろわない)
- 選択肢C: プロジェクトファイルの `codegen` に持つ(利点: 言語・出力先と同じ場所で、チームでそろう / 欠点: プロジェクトファイルの項目が増える)

### プロジェクトファイルを保存したときに生成するもの

- 選択肢A: プロジェクト全体(すべてのフォームと起動部分)(利点: 名前空間・`headerDir` などの変更がすぐ全体に反映される /
  欠点: 保存のたびに重く、ほかのフォームの検証エラーや手編集に巻き込まれる)
- 選択肢B: 起動部分だけ(利点: 軽く、プロジェクトファイルの保存の影響がそのファイルの生成に限られる / 欠点: 全体への反映は「プロジェクト全体のコードを生成」で行う)

### 生成する区間が手で編集されていたとき

- 選択肢A: 明示的な操作と同じく、モーダルのダイアログで聞く(利点: 振る舞いが同じ / 欠点: 保存のたびにダイアログが出る)
- 選択肢B: 上書きせずにやめ、モーダルでない通知で知らせる(利点: 保存を妨げない / 欠点: 通知を見落とすと生成されないままになる)

## 決定

有効・無効は選択肢C、プロジェクトファイルの保存は選択肢B、手編集は選択肢B にする。

### 設定

- プロジェクトファイルの `codegen.generateOnSave`(真偽値)。省略時は `true`(有効)。
- プロジェクトの設定画面の「コード生成」に、チェックボックス「保存時に生成」を置く。有効なら書かず、無効なら `false` を書く。
- フォームが複数のプロジェクトに属するときは、どれか 1 つでも無効なら生成しない(生成しない側に倒す)。

### 保存したときに生成するもの

- フォームを保存したら、そのフォームのコードを生成する。ハンドラの雛形の追記も、明示的な操作と同じく行う。
- プロジェクトファイルを保存したら、起動部分のコード(`Project1.cpp`・`Project1.py`)だけを生成する。
  - 加えたフォームが起動部分に入るように、ビューからのフォームの追加などでプロジェクトファイルが保存されたときも生成する。

### 明示的な操作との違い

保存したときは、ダイアログを出さない。

- どのプロジェクトにも属さないフォームは生成しない。プロジェクトへの追加は案内しない。
- 検証エラーがあれば生成しない。問題パネルに出ているので、通知は重ねない。
- 成功は、ステータスバーに短く出す。
- 警告(DSL から消えた名前など)は、出力のチャネルに書き、ステータスバーで知らせる。
- 生成する区間が手で編集されていれば、上書きしない。
  - モーダルでない通知で知らせ、その「上書き」から確認せずに生成し直せるようにする。
  - 答えを待たずに保存の処理を終える。

### 連続した保存

- 同じファイルの保存が続いたとき(自動保存など)は、生成を順に行って重ならないようにする。
- 内容が変わらなければ、生成先のファイルは書かない(これまでと同じ)。
- 生成先をエディタで開いていて未保存なら、未保存のまま差分を当てる(これまでと同じ)。手で書いた内容は失われない。

## 影響

- tk-designer ADR 0010 の「生成は利用者の明示的な操作で行う」を改める。明示的な操作(「コードを生成」「プロジェクト全体のコードを生成」)は残る。
- 既存のプロジェクトも、省略時が有効なため、更新すると保存したときに生成するようになる。拡張の CHANGELOG に書く。
- 名前空間・`headerDir` などの全体に関わる設定を変えたときは、これまでどおり「プロジェクト全体のコードを生成」で反映する。
- 手編集の通知を見落とすと、そのフォームのコードは古いままになる。手で生成すれば、これまでどおりモーダルで確かめて上書きできる。
